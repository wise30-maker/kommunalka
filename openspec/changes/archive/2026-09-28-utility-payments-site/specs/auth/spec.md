# Spec Delta

## Purpose

Ограничивает доступ к данным владельцу: только авторизованный пользователь
может просматривать и изменять платежи, объекты и отчёты.

## ADDED Requirements

### Requirement: Вход по email и паролю
Система SHALL требовать вход по email и паролю перед доступом к любым данным.
Система SHALL иметь ровно одного пользователя-владельца; регистрация новых
пользователей MUST быть недоступна.

#### Scenario: Доступ без входа
- **WHEN** неавторизованный посетитель открывает сайт
- **THEN** он видит только форму входа и не может просматривать данные

#### Scenario: Успешный вход
- **WHEN** посетитель вводит email и пароль владельца
- **THEN** он получает доступ к данным и остаётся в системе до выхода или истечения сессии

#### Scenario: Неверные учётные данные
- **WHEN** посетитель вводит неверный email или пароль
- **THEN** система сообщает об ошибке и не открывает доступ к данным

### Requirement: Защита данных на уровне базы
Система SHALL обеспечивать, что чтение и запись данных возможны только с
токеном авторизованного пользователя (правила доступа на уровне строк базы
данных), даже при прямом обращении к API извне приложения.

#### Scenario: Прямой запрос без токена
- **WHEN** внешний скрипт обращается к API базы данных без валидного токена
- **THEN** данные не возвращаются и не изменяются
