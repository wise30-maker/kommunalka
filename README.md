# kommunalka

Учёт коммунальных платежей по объектам недвижимости. Личный проект.
Статика на GitHub Pages + Supabase (Postgres, Auth).

- Сайт: https://wise30-maker.github.io/kommunalka/
- Задачи и спецификации: `openspec/changes/utility-payments-site/` (базовый функционал),
  `openspec/changes/receipt-ocr/` (распознавание квитанций по фото)

## Локальная разработка

Открыть `index.html` не получится (нужен конфиг Supabase) — см. `js/config.example.js`.

## Деплой

`python tools/deploy.py "сообщение коммита"` — публикация через GitHub API (git push в этой
сети не проходит). Скрипт:

- сам проставляет версии `?v=<sha8 содержимого>` для css/js в `index.html` (правки в браузере
  подхватываются без Ctrl+F5);
- загружает только изменившиеся файлы (сравнение git-hash с содержимым репозитория), поэтому
  7 МБ ассетов OCR в `vendor/` не перезаливаются при каждой правке.

## Ассеты OCR (`vendor/tesseract/`)

Локальное распознавание квитанций (Tesseract.js, WASM) — без LLM и без внешних сервисов:

- `tesseract.min.js`, `worker.min.js` — tesseract.js v5;
- `tesseract-core.wasm.js` — WASM-ядро (~4,7 МБ);
- `rus.traineddata.gz` — русский языковой пакет, вариант `4.0.0_best_int` (~2,7 МБ).

Источник: cdn.jsdelivr.net. Загружаются лениво при первом распознавании, дальше из кэша браузера.

## Отладка парсера без телефона

`tools/winocr.ps1` — распознавание изображения встроенным OCR Windows (WinRT, движок `ru`),
полностью локально. Использование:

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools/winocr.ps1 -Path "C:\путь\квитанция.png" -Out "$env:TEMP\receipt.txt"
```

Вывод пишется в UTF-8 (иначе кириллица ломается в консоли). Служит стендом для отладки
парсера `js/receipt-parse.js` на реальных скриншотах.

`tools/ocr_test.js` — прогон того же движка, что на сайте (Tesseract.js из `vendor/`), по
изображению с перебором режимов сегментации. Нужен установленный рядом `tesseract.js`:

```
npm install tesseract.js@5
NODE_PATH=<каталог>/node_modules node tools/ocr_test.js путь/к/квитанции.png      # перебор PSM
NODE_PATH=<каталог>/node_modules node tools/ocr_test.js путь/к/квитанции.png 11   # один режим, полный текст
```

Рабочий режим для квитанций — **PSM 11** (разрозненный текст): на тестовом скриншоте он единственный
верно распознал и все пять сумм, и итог «К оплате 8 292,04 ₽».

## Распознавание квитанций (локальное, без LLM)

В форме месяца есть кнопка **📷 С квитанции**: выбираете фото или скриншот платёжных документов —
суммы раскладываются по статьям расходов. Распознавание (Tesseract.js, WASM из `vendor/tesseract/`)
выполняется **целиком в браузере телефона или ПК**: изображение никуда не отправляется, языковые
модели не используются. Первая загрузка движка ~10 МБ, дальше — из кэша.

### Как это работает
1. **Заполните «Соответствие ГИС ЖКХ»** в настройках объекта (Настройки объекта → у каждой статьи
   поле «Соответствие ГИС ЖКХ»): укажите получателей платежа так, как они написаны в квитанции,
   через `;` — например `Водоканал;МУП города Хабаровска`, `Магнит;РЕГСТРОЙКОМ`, `ДЭК`.
   Парсер ищет статью по этому реквизиту (регистр, кавычки и типичные ошибки OCR не важны).
2. Откройте объект → «+ Новый месяц» → **📷 С квитанции** → выберите изображение.
3. Проверьте таблицу «Получатель → Статья → Сумма»: подставленные статьи и суммы можно править,
   строки без соответствия показываются как «— не выбрано —» (выберите статью вручную).
4. Нажмите **Применить** — суммы попадут в поля формы. В базу ничего не пишется до нажатия
   «Сохранить».

### Что стоит знать
- Несколько документов одного получателя складываются в одну статью (например, два документа
  «Магнит» → «Квартплата»).
- Если OCR потерял запятую в сумме («56756» вместо «567,56»), строка помечается как сомнительная
  и предлагается 567,56 — проверьте её глазами.
- Сверху превью сравнивается распознанная сумма с итогом «К оплате» из квитанции; расхождение
  показывается явно.
- Показания счётчиков распознаванием не разбираются — только суммы.

### Если что-то не распозналось
- Почистите скриншот: суммы должны быть видны целиком, без обрезки по краю.
- `test-ocr.html` на сайте — служебная страница: можно загрузить то же изображение и посмотреть
  сырой распознанный текст (кнопка «показать распознанный текст» есть и в превью).
- Для отладки на компьютере: `tools/ocr_test.js` (движок как на сайте, перебор режимов) и
  `tools/parse_test.js` (прогон парсера по тексту с набором статей).

## Показания счётчиков

Показания вводятся вручную (распознавание квитанций их не разбирает) и остаются **справочными**:
стоимость по расходу система не считает — суммы берутся из квитанции.

В форме месяца подсказки:
- над названием каждого счётчика — «предыдущие показания: <значение> (<период>)» из последнего
  заполненного месяца объекта;
- кнопка **«Заполнить по среднему (последние 3 месяца)»** — подставляет в пустые поля
  «последнее показание + средний месячный расход». Средний считается так: берутся последние
  4 показания счётчика (это 3 промежутка), суммарная разница делится на число промежутков.
  Нулевая разница = расход 0 (подставляется то же значение), убывающая (замена или сброс
  счётчика) в расчёт не берётся. Введённые вручную значения не перетираются; после заполнения
  выводится отчёт: сколько заполнено, где расход 0, где данных мало.

Подсказки и расчёты живут в `js/readings.js`; проверить их на реальной истории можно стендом:

```
node tools/readings_test.js 2026 "Фурманова 193"
```

## Поделиться отчётом

В разделе «Отчёты» под таблицей есть кнопка **«📤 Поделиться отчётом»** — открывает системное
меню телефона (мессенджеры, почта, заметки) через Web Share API. Текст отчёта — список объектов
с суммами и итог. Под графиками отдельные кнопки **«📤 Поделиться графиком»** — отправляют PNG.
Если системное меню недоступно (например, браузер на ПК), текст копируется в буфер обмена,
а картинка скачивается в загрузки.

## Доступность (пауза Supabase на free tier)

Симптом: сайт открывается, но сразу показывает **«Failed to fetch»** — до отправки логина.
Это не ошибка фронтенда и не сломанный деплой: бесплатный тариф Supabase усыпляет проект
после ~7 дней без запросов, и у усыплённого проекта **пропадает DNS-запись** (NXDOMAIN),
поэтому браузер не может даже установить соединение. Проверка «фронтенд или бэкенд»:

```
curl -s -o /dev/null -w '%{http_code}\n' https://wise30-maker.github.io/kommunalka/   # 200 → Pages жив
nslookup jtooyjofbosgspeonaza.supabase.co                                             # NXDOMAIN → проект спит
curl -s -H "Authorization: Bearer $(cat ~/.kommunalka-supabase-token)" \
  https://api.supabase.com/v1/projects/jtooyjofbosgspeonaza                           # status: INACTIVE
```

Разбудить: `POST https://api.supabase.com/v1/projects/jtooyjofbosgspeonaza/restore`
(тем же PAT) либо кнопкой Restore в дашборде — https://supabase.com/dashboard/project/jtooyjofbosgspeonaza .
Поднимается за минуту-две; `ref` и ключи не меняются, деплой сайта не нужен.

Чтобы проект не засыпал, работают две независимые «пинговалки» — обе бьют **в базу**
(PostgREST), а не в health:

1. **GitHub Actions** — `.github/workflows/supabase-keepalive.yml`, каждые 2 дня в облаке.
   Сбой job'а и отключение расписания GitHub'ом приходят письмом владельцу репозитория.
2. **Локальный планировщик Hermes** — `~/AppData/Local/hermes/scripts/kommunalka-keepalive.py`
   (задание `kommunalka-supabase-keepalive`, ежедневно 9:00): пингует базу, а если проект всё же
   уснул — сам вызывает `restore` и ждёт `ACTIVE_HEALTHY`. Молчит, когда всё хорошо; пишет отчёт
   только при проблеме. Работает лишь при запущенном Hermes.

   Автозапуск gateway настроен (2026-10-26): `hermes gateway install --start-now --start-on-login`.
   Задача в Планировщике Windows не создалась — UAC на этой учётке недоступен (ShellExecuteW=5),
   Hermes сам ушёл в fallback: ярлык автозагрузки
   `…\Start Menu\Programs\Startup\Hermes_Gateway.vbs` (запускает
   `…\Local\hermes\gateway-service\Hermes_Gateway.cmd` без окна). Проверка — `hermes gateway status`
   (должно быть `✓ Gateway process running`), в `logs\gateway.log` строка
   `Cron scheduler will tick 1 profile(s)`. Если после правки скрипта задания «молчат» —
   сначала смотреть этот статус: без gateway тикер не работает, хотя само задание и
   `last_status: ok` остаются на месте.

**Важно (проверено 2026-10-22).** Пинг `GET /auth/v1/health` keep-alive НЕ даёт: без `apikey`
Kong отвечает 401 ещё на входе, запрос не доходит до Postgres и активностью базы не считается.
23 сентября – 22 октября обе «пинговалки» рапортовали «жив», а база всё равно уснула. Рабочий
пинг — REST-запрос с anon-ключом, он реально исполняется в базе:

```
curl -s -o /dev/null -w '%{http_code}\n' -H "apikey: $ANON" -H "Authorization: Bearer $ANON" \
  "https://jtooyjofbosgspeonaza.supabase.co/rest/v1/objects?select=id&limit=1"   # 200 → база жива
```

`200` с телом `[]` — норма (RLS режет строки без логина, но запрос дошёл до Postgres).
anon-ключ берётся из `js/config.js`; в workflow он лежит открытым текстом осознанно — он и так
публикуется на сайте, доступ закрыт RLS. При ротации ключей обновить оба места.

Проверить сам скрипт: `python ~/AppData/Local/hermes/scripts/kommunalka-keepalive.py`
(пустой вывод = проект жив) и `--simulate-fail` (прогон ветки сбоя).
